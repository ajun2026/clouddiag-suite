# 架构说明

## 整体结构

```
┌─────────────┐         ┌──────────────────┐         ┌─────────────────┐
│   浏览器     │ ←─────→ │ clouddiag-server │ ←─────→ │ clouddiag-bridge│
│ （工程师）   │  WS/HTTP│  （云端诊断服务）  │   WS    │ （客户机桥接器） │
└─────────────┘         └──────────────────┘         └─────────────────┘
                                  │                            │
                                  │ HTTP                       │ 执行诊断命令
                                  ↓                            ↓
                        ┌──────────────────┐         ┌─────────────────┐
                        │  log-analyzer    │ ←────── │  日志包上传      │
                        │  （日志分析服务）  │  上传    │ （客户机本地）    │
                        └──────────────────┘         └─────────────────┘
```

## 三个部件

### clouddiag-server（云端诊断服务）

| 项 | 说明 |
|---|---|
| 技术栈 | Python + FastAPI + WebSocket |
| 端口 | 默认 8000（可配） |
| 职责 | 账号登录、房间管理、诊断台页面、AI 分析编排、工具下发、IDG 转发 |
| 前端 | 登录页 / 工作台 / 对话页 / 诊断台（纯 HTML+JS，无构建步骤） |
| 数据 | SQLite（房间、消息、账号） |

**关键机制**

- **房间**：创建诊断会话，生成 8 位房间码；桥接器凭房间码+令牌接入
- **诊断台**：30 个诊断项，点击后由 AI 按标准流程采集，输出五段式结构化报告
- **审批**：涉及修改类操作时弹窗确认（Tier 2/3 安全边界）
- **IDG 转发**：采集的日志包可一键上传到 log-analyzer

### clouddiag-bridge（客户机桥接器）

| 项 | 说明 |
|---|---|
| 技术栈 | **Go**（单一源码，交叉编译多平台） |
| 产物 | Windows amd64 / Linux amd64 / arm64 / loong64 |
| 职责 | 连接云端、接收命令、在客户机执行、回传结果、上传日志包 |
| 设计原则 | 只管「命令管道 + 文件通道」，不内置业务逻辑；命令本地可审计 |

**安全边界**：桥接器不在后台静默运行、不自启动、不主动提权（Windows 提权需用户确认 UAC）。

### log-analyzer（日志分析服务）

| 项 | 说明 |
|---|---|
| 技术栈 | Python + FastAPI |
| 端口 | 默认 8082（可配） |
| 进程 | `main.py`（Web 服务）+ `deep_analyze_consumer.py`（AI 分析后台消费者） |
| 职责 | 接收日志包 → 识别格式 → 解压 → 解析 → 生成报告 / AI 分析 |

**支持的日志格式**：`.zip` / `.7z` / `.rar` / `.tar.gz` / `.tar.xz` / `.tzz`（IBM XCC FFDC）

**日志类型**：Windows（事件日志/dump/SMART/RAID/SIO）、Linux（sosreport 等）、BMC/XCC

## 数据流

### 诊断流程

```
工程师创建工作台房间
   ↓ 生成房间码 + 令牌
客户机运行桥接器（一键连接命令）
   ↓ WS 连接云端
工程师在诊断台选择诊断项
   ↓ 云端 AI 编排命令序列
桥接器在客户机执行命令
   ↓ 回传结果
云端 AI 分析 → 五段式报告（采集项/观察/依据/缺失/初步判读）
```

### 日志分析流程

```
客户机工具采集日志 → 打包
   ↓ 一键上传（HTTP multipart）
clouddiag-server 校验令牌 → 转发 log-analyzer
   ↓ 解压 + 格式识别
解析 + AI 分析 → 报告（网页查看）
```

> 采集与分析**解耦**：日志包上传后即使桥接器断开，分析仍可继续。

## 部署形态与架构的关系

**架构不依赖 TLS / 域名 / 证书**。项目只监听 HTTP 端口：

- **纯 HTTP 部署**：浏览器/桥接器直连服务端口
- **HTTPS 部署**：前面加一层反向代理（Caddy/Nginx）终结 TLS

两种形态下**代码完全相同**，仅环境变量与是否套代理不同。详见 [部署指南](01-部署指南.md)。

│   ├── main.py

│   ├── analyzers/        # 各平台分析模块
│   └── .env.example
