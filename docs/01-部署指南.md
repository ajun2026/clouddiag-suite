# 部署指南

本文档覆盖两种部署形态，请先确认你的场景：

| 场景 | 你有 | 走哪节 |
|---|---|---|
| **A** | 一台 Linux 服务器 + 公网 IP，**没有域名** | [场景 A：纯 HTTP 部署](#场景-a纯-http-部署无域名) |
| **B** | 域名（可解析到服务器）+ 服务器 | [场景 B：域名 + HTTPS 部署](#场景-b域名--https-部署) |

> 🔑 **核心原则**：项目代码本身**不含**任何 TLS / 域名 / 证书依赖。
> 它只监听 HTTP 端口；是否在其前面加一层反向代理做 HTTPS，是**部署选择**，不是代码要求。

---

## 场景 A：纯 HTTP 部署（无域名）

**适合**：内网环境、临时验证、只有 IP 的服务器。
**特点**：零额外组件（不需要域名、不需要证书、不需要反向代理）。

### A1. 安装系统依赖

```bash
sudo apt update
sudo apt install -y python3 python3-pip python3-venv p7zip-full lzop
# unrar（可选，但建议装——rar 解压兜底）
sudo apt install -y unrar || sudo apt install -y unrar-free
```

### A2. 获取代码

```bash
sudo mkdir -p /opt/clouddiag && sudo chown $USER /opt/clouddiag
git clone https://github.com/ajun2026/clouddiag-suite.git /opt/clouddiag
cd /opt/clouddiag
```

### A3. 部署 clouddiag-server（诊断服务）

```bash
cd /opt/clouddiag/clouddiag-server
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

cp .env.example .env
```

编辑 `.env`（**HTTP 场景的关键配置**）：

```ini
# —— 监听 ——
SERVER_HOST=0.0.0.0
SERVER_PORT=8000

# —— 对外地址（★必须改成你的 IP:端口）——
PUBLIC_URL=http://1.2.3.4:8000

# —— ★★ HTTP 环境必须设为 false，否则登录后立刻掉线 ★★——
COOKIE_SECURE=false

# —— AI 大脑 ——
AGENT_BRAIN=deepseek
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_API_KEY=sk-your-key-here
OPENAI_MODEL=deepseek-chat

# —— 桥接器上传校验密钥（改为随机值）——
BRIDGE_HTTP_SECRET=change-me-to-a-random-string

# —— 管理员账号 ——
ADMIN_USERNAME=admin
ADMIN_PASSWORD=change-me

# —— 对接日志分析服务（见 A4 部署后的端口）——
LOG_ANALYZER_UPSTREAM=http://127.0.0.1:8082
LOG_ANALYZER_DIR=/opt/clouddiag/log-analyzer
```

启动：

```bash
./start_cab.sh          # 前台启动（首次调试用，Ctrl+C 停止）
```

验证：浏览器打开 `http://1.2.3.4:8000` → 应看到登录页。

### A4. 部署 log-analyzer（日志分析服务）

```bash
cd /opt/clouddiag/log-analyzer
python3 -m venv venv
./venv/bin/pip install -r requirements.txt

cp .env.example .env
```

编辑 `.env`：

```ini
# 端口（与 clouddiag-server 的 LOG_ANALYZER_UPSTREAM 保持一致）
PORT=8082

# —— AI 通道（与诊断服务可共用同一 key）——
DEEPSEEK_BASE_URL=https://api.deepseek.com/v1
DEEPSEEK_API_KEY=sk-your-key-here
DEEPSEEK_MODEL=deepseek-chat

# —— 可选：备用通道（主通道失败时自动切换）——
# DEEPSEEK_BASE_URL_2=
# DEEPSEEK_API_KEY_2=
# DEEPSEEK_MODEL_2=
```

启动：

```bash
./venv/bin/python main.py        # 前台启动
# 或后台 + 日志：
nohup ./venv/bin/python main.py > la.log 2>&1 &
```

验证：`curl http://127.0.0.1:8082/` → 返回 200。

### A5. 配置为开机自启（systemd）

**clouddiag-server**：

```bash
sudo tee /etc/systemd/system/clouddiag-server.service > /dev/null << 'EOF'
[Unit]
Description=CloudDiag Server (AI Remote Diagnostics)
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/clouddiag/clouddiag-server
ExecStart=/opt/clouddiag/clouddiag-server/venv/bin/python server.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF
```

**log-analyzer**：

```bash
sudo tee /etc/systemd/system/clouddiag-loganalyzer.service > /dev/null << 'EOF'
[Unit]
Description=CloudDiag Log Analyzer (IDG)
After=network.target

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/clouddiag/log-analyzer
ExecStart=/opt/clouddiag/log-analyzer/venv/bin/python main.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

# 深度分析消费者（AI 分析后台进程）
sudo tee /etc/systemd/system/clouddiag-logconsumer.service > /dev/null << 'EOF'
[Unit]
Description=CloudDiag Log Analyzer - Deep Analysis Consumer
After=network.target clouddiag-loganalyzer.service

[Service]
Type=simple
User=ubuntu
WorkingDirectory=/opt/clouddiag/log-analyzer
ExecStart=/opt/clouddiag/log-analyzer/venv/bin/python deep_analyze_consumer.py
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl daemon-reload
sudo systemctl enable --now clouddiag-server clouddiag-loganalyzer clouddiag-logconsumer
sudo systemctl status clouddiag-server --no-pager
```

### A6. 开放端口

```bash
# 云服务器：在控制台安全组放行 8000（以及 8082，如需从外部访问日志分析页）
# 本机防火墙（如启用了 ufw）：
sudo ufw allow 8000/tcp
sudo ufw allow 8082/tcp
```

### A7. 验证

```bash
bash /opt/clouddiag/deploy/doctor.sh
```

## 场景 B：域名 + HTTPS 部署

**适合**：对外服务、需要 HTTPS 加密、有域名的环境。
**特点**：在场景 A 的基础上，前面套一层反向代理（Caddy 自动申请证书）。

> ⚠️ 与场景 A 的**唯一区别**是：环境变量 + 反向代理配置。项目代码完全一致。

### B1. 前置条件

```
① 域名已解析到服务器公网 IP（A 记录）
② 服务器 80 和 443 端口对外开放（Let's Encrypt 验证需要 80）
③ 已完成场景 A 的 A1-A4 步（服务已能通过 HTTP 访问）
```

### B2. 安装 Caddy

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

### B3. 配置 Caddyfile

```bash
sudo cp /opt/clouddiag/deploy/domain-https/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile      # 把 your-domain.com 改成你的域名
```

Caddyfile 内容：

```
your-domain.com {
    # 诊断服务（主站）
    handle_path /log-analyzer/* {
        reverse_proxy 127.0.0.1:8082
    }
    reverse_proxy 127.0.0.1:8000

    # 大文件上传支持
    request_body {
        max_size 500MB
    }

    # 自动申请并续期 Let's Encrypt 证书（无需手工配置）
}

# 备选端口 8443（应对某些网络对 443 的拦截，可选）
your-domain.com:8443 {
    handle_path /log-analyzer/* {
        reverse_proxy 127.0.0.1:8082
    }
    reverse_proxy 127.0.0.1:8000
}
```

```bash
sudo systemctl reload caddy
sudo systemctl status caddy --no-pager
```

### B4. 修改环境变量（与场景 A 的差异）

`clouddiag-server/.env`：

```ini
# ★ 改为域名 + https
PUBLIC_URL=https://your-domain.com

# ★ HTTPS 环境设为 true（安全）
COOKIE_SECURE=true
```

`log-analyzer/.env`：无需改动（它只在本地被代理访问）。

### B5. 重启服务

```bash
sudo systemctl restart clouddiag-server clouddiag-loganalyzer
```

### B6. 验证

```bash
curl -I https://your-domain.com          # 应返回 200，证书有效
bash /opt/clouddiag/deploy/doctor.sh --url https://your-domain.com
```

## 常见部署陷阱（务必先看）

| 陷阱 | 现象 | 解决 |
|---|---|---|
| `COOKIE_SECURE` 配错 | HTTP 环境设 true → 登录后立刻掉线 | HTTP 用 `false`，HTTPS 用 `true` |
| 缺解压工具 | 上传 .7z/.rar/.tzz 报「服务器错误」 | 装 `p7zip-full` + `unrar` + `lzop` |
| 缺 Python 依赖 | 启动报 ImportError / AI 功能报 `Bearer` 错 | `pip install -r requirements.txt`（含 python-multipart / python-dotenv） |
| 端口不一致 | 诊断服务调不到日志分析 | 两边端口对齐（`LOG_ANALYZER_UPSTREAM` ↔ log-analyzer 的 `PORT`） |
| 桥接器协议错 | 桥接器连不上服务器 | HTTP 部署 → 桥接器用 `ws://`；HTTPS → `wss://` |
| 用文件覆盖升级 | 把现网修复覆盖回旧版 | 升级时按文件比对，或先备份（见[风险记录 D1](风险与事故记录/)） |
| `.env` 提交仓库 | 凭据泄露 | `.env` 永不入库（见[事故记录 C1](风险与事故记录/)） |

## 端口规划建议

| 服务 | 默认端口 | 说明 |
|---|---|---|
| clouddiag-server | 8000 | 主服务（HTTP） |
| log-analyzer | 8082 | 日志分析（HTTP，通常只本机访问） |
| Caddy | 80 / 443 | 仅 HTTPS 形态；443 被拦截时可加 8443 |

> 端口全部可通过环境变量修改，无需改代码：
> - server：`SERVER_HOST` / `SERVER_PORT`
> - log-analyzer：`PORT` / `HOST`

## 升级与回退

### 升级前（必做）

```bash
# 备份（含运行时数据）
TS=$(date +%Y%m%d-%H%M)
mkdir -p ~/backups/$TS
tar -czf ~/backups/$TS/clouddiag-suite.tar.gz -C /opt/clouddiag --exclude=venv .
```

### 升级

```bash
cd /opt/clouddiag
git fetch --tags && git checkout v1.0.1        # 切到目标版本
# 按文件核对差异（避免把现网修复覆盖回旧版）
git diff v1.0.0 v1.0.1 --stat
./venv/bin/pip install -r requirements.txt     # 如有依赖变化
sudo systemctl restart clouddiag-server clouddiag-loganalyzer clouddiag-logconsumer
```

### 回退

```bash
cd /opt/clouddiag && git checkout v1.0.0
sudo systemctl restart clouddiag-server clouddiag-loganalyzer clouddiag-logconsumer
# 或从备份恢复：
# tar -xzf ~/backups/<TS>/clouddiag-suite.tar.gz -C /opt/clouddiag
```
