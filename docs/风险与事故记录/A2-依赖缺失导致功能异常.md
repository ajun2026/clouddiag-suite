# A2 · 依赖缺失导致启动或功能失败

**类别**：部署
**状态**：✅ 已补全依赖清单

---

## 现象

两类典型故障，都源于**依赖未声明或系统工具缺失**：

| 现象 | 缺失项 |
|---|---|
| 服务启动后 AI 功能全不可用，报 `legal header value b'Bearer'` | `python-dotenv` 未安装 → `.env` 未加载 → API Key 为空 |
| 文件上传接口报错、服务无法正常处理上传 | `python-multipart` 未安装 |
| 上传 `.7z` / `.rar` / `.tzz` 日志包报「服务器错误」或「日志目录不存在」 | 系统缺 `7z` / `unrar` / `lzop` |

---

## 根因

1. **Python 依赖清单不完整**：代码中 `from dotenv import load_dotenv`、
   FastAPI 的 `UploadFile`（需 `python-multipart`），但 `requirements.txt` 未声明。
2. **系统工具依赖未在文档中强调**：`.rar` 解压曾直接调用 `unrar`，
   而部分发行版/镜像未收录该包（版权原因），导致解压抛 `FileNotFoundError`，
   异常未被捕获 → 返回 500 HTML → 前端显示 `Unexpected token 'I', "Internal S"...`。

---

## 影响范围

- 新部署环境**必然复现**（依赖清单不全 = 部署方必然踩坑）
- 影响 AI 功能（全部不可用）与日志上传功能（全部失败）

---

## 处置过程

| 措施 | 说明 |
|---|---|
| 补全 `requirements.txt` | 加入 `python-dotenv`、`python-multipart` |
| 解压改为**双保险** | `.rar` 解压：`7z` 优先（`p7zip-full` 几乎处处可用且支持 rar/rar5），失败再走 `unrar` |
| 解压异常**结构化返回** | 解压失败返回 JSON（含原因与支持的格式提示），不再抛 500 裸错误页 |
| 文档补充**部署必查项** | 压缩工具缺失后果对照表 + 自查命令 |

### 部署后自查命令

```bash
# 1) 压缩工具是否齐全
which 7z unrar lzop

# 2) 7z 是否支持 rar
7z i | grep -i rar

# 3) Python 依赖
./venv/bin/pip list | grep -E "dotenv|multipart"
```

---

## 预防措施

1. **依赖清单必须与代码 import 一致**（可定期用脚本扫描 import 与 requirements 的差异）
2. **外部命令调用要有兜底与异常捕获**，不能假设系统一定有某个工具
3. **部署文档列出「缺失后果」**，而不只是「要装什么」
