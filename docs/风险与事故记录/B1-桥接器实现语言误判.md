# B1 · 桥接器实现语言误判

**类别**：开发 / 认知
**状态**：✅ 已澄清

---

## 现象

开发过程中，误以为客户机桥接器是 **Python** 实现（因仓库中存在 `bridge.py`），
据此修改了 `bridge.py`，并尝试用 `wine` 打包 Windows 可执行文件，走了弯路。

实际上桥接器的**当前实现是 Go**（`clouddiag-bridge/*.go`，架构代号 "go-pipe"），
`bridge.py` 是历史遗留的 v1 版本，早已不参与构建与分发。

---

## 根因

1. **仓库中同时存在新旧两套实现**（`bridge.py` 旧 Python v1 + `*.go` 新 Go v2），
   旧文件未被清理或标注，容易误判。
2. **改动前未确认实际运行组件**——没有先查「分发的是哪个二进制、由哪份源码构建」。

---

## 影响

- 修改了错误的文件（对实际分发的桥接器无任何作用）
- 尝试用不合适的工具链（`wine`）打包，浪费时间
- 若未及时发现，可能发布出「改了但没生效」的版本

---

## 处置过程

| 措施 | 说明 |
|---|---|
| 明确桥接器实现 | Go 源码位于 `clouddiag-bridge/`，交叉编译产出 Windows / Linux 多平台二进制 |
| 清理旧实现 | 移除遗留的 `bridge.py` 及旧的 PyInstaller 产物 |
| 统一构建方式 | 用 Go 交叉编译（无需 wine / PyInstaller） |

### 正确的构建方式

```bash
cd clouddiag-bridge
# 由 build.sh 统一交叉编译
CGO_ENABLED=0 GOOS=windows GOARCH=amd64 go build -ldflags="-s -w" -o clouddiag-bridge-win64.exe .
CGO_ENABLED=0 GOOS=linux   GOARCH=amd64 go build -ldflags="-s -w" -o clouddiag-bridge-linux-amd64 .
```

---

## 预防措施

1. **改动代码前，先确认「实际运行的是哪个组件、由哪份源码构建」**
2. 仓库不留「同功能的旧实现」——要么删除，要么明确标注为历史归档
3. 构建方式写进文档（`clouddiag-bridge/build.sh` + README）
