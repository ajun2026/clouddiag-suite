# A5 · 桥接器无限重连（房间失效后空转上千次）

**发生时间**：2026-09-25
**类别**：部署 / 运维
**严重度**：🟡 中（不影响诊断功能，但客户端空转、日志暴涨、用户困惑）

---

## 现象

客户机上的桥接器日志（`~/.clouddiag/bridge.log`）出现连续重连：

```
14:07:44 已连接房间 EPP8PPB3
14:07:44 server error: 房间已闲置。请回到对话页重新获取一键连接（自动生成新令牌）。
14:07:44 连接被服务器正常关闭: websocket: close 1000 (normal)
14:07:44 连接断开 (第 1388 次): websocket: close 1000 (normal)，48s 后重连…
14:08:32 已连接房间 EPP8PPB3
14:08:32 server error: 房间已闲置。请回到对话页重新获取一键连接（自动生成新令牌）。
…
```

**连续重连 1392 次、每次间隔 48 秒，合计空转约 18.5 小时。**

---

## 根因

桥接器的重连循环**不区分断开原因**，任何断开都无条件重连：

```go
for {
    err := c.connectAndServe()
    c.cfg.Logger.Warn("连接断开 (第 %d 次): %v，%s 后重连…", attempt, err, backoff)
    time.Sleep(backoff)
    backoff *= 2
}
```

而服务端对"房间已闲置 / 令牌失效 / 房间不存在"这类情况是**永久性拒绝**——
重连多少次都不会成功，只会：

1. 客户端无限空转（CPU/网络/日志持续消耗）
2. 用户只看到"一直连不上"，**不知道要回网页重新获取连接命令**
3. 服务端被无效连接反复冲击（虽被正确拒绝，但产生大量日志噪音）

触发条件：诊断结束后工程师**没有关闭桥接器**，房间随后被标记为闲置。

---

## 修复

按"**区分临时故障与永久拒绝**"改造 `ws.go`（3 处改动）：

```go
// ① Run()：永久拒绝 → 打印指引并退出（不再重连）
if isPermanentReject(err) {
    c.cfg.Logger.Error("连接被服务器永久拒绝：%v", err)
    c.cfg.Logger.Error("该房间已失效（闲置/过期/令牌无效）。")
    c.cfg.Logger.Error("请在浏览器打开诊断台，点击「连接你的电脑」重新获取一键连接命令后重试。")
    c.cfg.Logger.Error("桥接器停止重连并退出。")
    return
}
// 其余情况：指数退避重连（3s→6s→12s→24s→30s 封顶）

// ② dispatch()：服务端用 error 消息告知永久拒绝 → 转成 permanentRejectError
case "error":
    if content != "" && isPermanentReject(fmt.Errorf("%s", content)) {
        return &permanentRejectError{Reason: content}
    }

// ③ connectAndServe()：永久拒绝错误向上传播，不被"处理消息出错"吞掉
```

### 拒绝原因匹配（中英文全覆盖）

服务端拒绝语有中英文两种，关键词必须都覆盖：

| 类型 | 关键词 |
|---|---|
| 中文 | 房间已闲置 / 房间不存在 / 房间已过期 / 令牌失效 / 令牌无效 / 重新获取一键连接 |
| 英文 | Room not found / Room expired / bad token / Invalid token / Create it from the dashboard |
| HTTP | 400 / 401 / 403 / 404 / 410 |

---

## 教训

1. **重连必须区分"可恢复"与"不可恢复"**——网络抖动要重连，服务端明确拒绝不要重连。
2. **匹配服务端提示要覆盖全部语言**：本项目服务端部分提示为英文，首版修复只因关键词写成中文而**未生效**（实测后发现并补全）。
3. 面向用户的失败提示要**给出下一步动作**（"回网页重新获取连接"），而不是只报错。
4. 长跑循环要设**上限或终止条件**，避免"静默空转"这类看不见的资源消耗。

./clouddiag-bridge-linux-amd64 -server ws://127.0.0.1:8000 -room <真实房间> -token bad  # 令牌失效
# 房间闲置：DB 中 UPDATE rooms SET status='idle' 后连接
