# D1 · 服务进程被连带杀死

**类别**：运维
**状态**：✅ 已用 systemd 解决

---

## 现象

服务运行一段时间后意外中断；或服务器重启后服务没有自动恢复。

---

## 根因

1. **进程未脱离父进程组**：服务以子进程方式启动（其父进程可能是会话管理器/网关进程），
   父进程重启或退出时，子进程被连带终止。
2. **未配置开机自启**：服务器重启后需要手工重新拉起服务，容易遗忘。

---

## 处置过程

统一改用 **systemd 托管**（`systemctl enable --now`），获得：

| 能力 | 说明 |
|---|---|
| 进程独立 | 脱离父进程组，不受上游进程生命周期影响 |
| 开机自启 | 服务器重启后自动恢复 |
| 崩溃自动重启 | `Restart=always` + `RestartSec=5` |
| 日志统一 | `journalctl -u <服务名>` 查看 |

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now clouddiag-server clouddiag-loganalyzer clouddiag-logconsumer
sudo systemctl status clouddiag-server --no-pager
journalctl -u clouddiag-server -n 50 --no-pager
```

---

## 预防措施

1. **生产环境服务一律用 systemd（或同类进程管理器）托管**，不要裸跑 + `nohup`
2. 配置 `Restart=always`，避免偶发崩溃后长期不可用
3. 部署文档包含 systemd unit 示例（见 [部署指南 A5](../01-部署指南.md#a5-配置为开机自启systemd)）
