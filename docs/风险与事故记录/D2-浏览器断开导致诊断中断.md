# D2 · 浏览器断开导致诊断任务中断

**发生时间**：2026-09-24
**类别**：运维 / 稳定性
**严重度**：🟡 中（诊断跑到一半前功尽弃，工程师需重来）

---

## 现象

诊断执行中，如果浏览器页面被**关闭 / 刷新 / 导航离开 / 网络抖动**，服务端日志出现：

```
[ERROR] Agent error in room EPP8PPB3
Traceback (most recent call last):
  ...
  File "server.py", line 3410, in run_agent
    await browser_ws.send_json({...})
starlette.websockets.WebSocketDisconnect: code 1006
```

**整个诊断 Agent 抛异常终止**，已执行的命令结果虽在库中，但最终报告不再生成。
实测：一个跑了约 2 分钟的诊断，工程师关一下页面就**全部白跑**。

---

## 根因

`run_agent()` 里向浏览器推送进度时**直接 await WebSocket 发送**，没有异常保护：

```python
await browser_ws.send_json({"type": "tool_result", ...})   # 客户端已断开 → 抛异常
```

一旦浏览器 WebSocket 关闭，`send_json` 抛 `WebSocketDisconnect`，
异常沿调用栈冒泡，令整个 Agent 循环退出。

（`agent_runner()` 里已有 `safe_send()` 包装，但 `run_agent()` 内部没有。）

---

## 修复

在 `run_agent()` 入口定义局部 `safe_send()`，并替换内部**全部 7 处**发送：

```python
_ws_closed = False

async def safe_send(payload: dict) -> bool:
    nonlocal _ws_closed
    if _ws_closed:
        return False
    try:
        # 必须用 browser_ws.send_json —— 写成 safe_send 会无限递归
        await browser_ws.send_json(payload)
        return True
    except Exception as e:
        _ws_closed = True
        run_logger.warning(f"[{room.code}] browser send failed (client gone?): {e}")
        return False
```

要点：
- 首次失败即打标记 `_ws_closed`，后续不再尝试发送（避免反复抛异常）
- **推送失败绝不影响诊断继续执行与结果落库**（`save_message` 不受影响）
- 诊断结果写入 DB，页面重新打开会加载最近一次输出

---

## 修复过程中的二次踩坑（重要）

批量替换 `await browser_ws.send_json(` → `await safe_send(` 时，
**把 `safe_send` 函数体内部的 `browser_ws.send_json` 也替换了**，导致自我调用：

```python
async def safe_send(payload):
    await safe_send(payload)   # ❌ 无限递归
```

实测报错 `maximum recursion depth exceeded while calling a Python object`。
修正：函数体内必须显式使用 `browser_ws.send_json`。

**教训**：批量文本替换后必须**逐一核对替换点**（尤其函数定义体内部），
并跑一次真实链路验证（本次即通过实测发现）。

---

## 验证

```
场景：诊断执行中关闭浏览器页面
修复前：Agent error in room（诊断中断）
修复后：
  ✅ 诊断完整跑完（AI 输出 4638 字符报告）
  ✅ 结果已落库（数据库可查）
  ✅ 无 Agent error，仅一条正常日志 "[browser] left room"
```

---

## 教训

1. **推送进度是"尽力而为"**——任何面向 UI 的发送都必须包异常处理，不能让它影响主业务。
2. **诊断任务应独立于连接生命周期**：客户端断开 ≠ 任务取消。
3. 批量文本替换是高风险操作，替换后要检查**是否命中了函数自身实现**。
4. 修复必须**用真实场景验证**（本次用"关页面"实测，才发现了递归问题）。
