# E1 · 诊断项未按客户机系统过滤

**发生时间**：2026-09-23 ~ 09-24
**类别**：产品 / 交互
**严重度**：🟡 中（客户拿到跑不通的诊断项、复制到语法错误的命令）

---

## 现象（两个相关缺陷）

### 缺陷 1：Linux 房间显示 Windows 专属诊断项

诊断台（`/diag`）左侧 30 个诊断项里，有 23 个是 Windows 专属
（蓝屏分析、电池健康、BitLocker/TPM、系统激活、RAID 阵列、独显启用状态…）。

**Linux 房间**打开诊断台时，这些项**照常显示**——点下去必然失败或答非所问。

### 缺陷 2：Linux 房间默认推送 PowerShell 命令

「连接你的电脑」面板固定选中 **PowerShell 命令（推荐）**，
即使诊断台已显示"本房间系统：linux"。

客户直接点「复制命令」→ 拿到 PowerShell 语法 → 粘到 Linux 终端：

```
bash: 未预期的符号 `{' 附近有语法错误
```

进一步排查发现**更深一层**的问题：即使切到 Linux 页签，命令仍是 PowerShell 的——
因为取命令的键名写错了：

```javascript
// 服务端返回 conn = { powershell, windows_bat, linux }
text = conn.linux_sh ? ... : conn.powershell   // ❌ linux_sh 不存在 → 永远回退 PowerShell
```

---

## 根因

1. **诊断项定义里有 `platform` 字段（all/win/linux），前端却完全没用**——
   `diag.html` 硬编码 30 张卡片，不按房间系统过滤。
2. **连接面板页签固定选中 PowerShell**，不随房间系统切换；
   且 Linux 分支的取值键名错误（`conn.linux_sh` → 应为 `conn.linux`）。

---

## 修复

### ① 诊断项按系统过滤

```javascript
function applyDiagItemsByOS(osRaw) {
  const isLinux = (osRaw || 'windows').toLowerCase() === 'linux';
  document.querySelectorAll('.tags-panel .diag-card').forEach(card => {
    const pf = (card.dataset.platform || 'all').toLowerCase();
    // linux 房间 → all + linux；windows 房间 → all + win
    const visible = (pf === 'all') || (isLinux ? pf === 'linux' : pf === 'win');
    card.style.display = visible ? '' : 'none';
  });
  // 同时隐藏因此变空的分组标题
  ...
}
```

在 `loadRoomInfo()` 拿到 `d.os` 后调用。

### ② 连接面板只显示对应系统的方式

```javascript
function applyConnectTabsByOS() {
  const isLinux = (roomConnData.os || '').toLowerCase() === 'linux';
  // 不匹配的页签直接隐藏（不只是不选中）
  document.querySelectorAll('#cp-tabs .cp-tab').forEach(btn => {
    const tabOS = (btn.dataset.os || 'windows').toLowerCase();
    btn.style.display = (isLinux ? tabOS === 'linux' : tabOS === 'windows') ? '' : 'none';
  });
  ...
}

// 取命令的键名修正
text = conn.linux || (dl.linux_sh ? ... : '') || '（未获取到 Linux 命令）';
```

### ③ 新增 10 个 Linux 专属诊断项

`quick_diagnoses.json` 补齐（platform=`linux`），覆盖真实 Linux 排障场景：

| 分组 | 诊断项 |
|---|---|
| 系统诊断 | 内核日志 · 系统服务 · 启动失败 · 内存与 OOM · 包管理状态 |
| 硬件诊断 | 磁盘与文件系统 · 温度与风扇 |
| 外设网络 | 网络配置 · USB 与 PCI 设备 |
| 实用工具 | 日志与空间治理 |

每个都带完整五段式提示词（采集项/观察/依据/缺失/初步判读）。

最终分布：**all 7 + win 23 + linux 10 = 40 项**，按房间系统各自呈现 17 / 30 项。

---

## 附带修复的布局 bug

批量插入 Linux 卡片时，**"实用工具"是最后一个分组**，
插入点计算把它落到了 `</body>` 前 → 卡片脱离左侧面板、**占据整屏宽度、把底部输入栏挤上去**。

修复：按分组的最后一个卡片定位插入点，并对面板内外做**标签平衡校验**（`<div>` 244 vs `</div>` 244）。

---

## 教训

1. **数据字段定义了就要用**——`platform` 字段早就存在，前端不用等于没有。
2. **"默认值"要跟随上下文**：房间系统决定命令形态，不能固定推荐一种。
3. **键名错误会静默降级**：`conn.linux_sh` 取不到值时不报错，而是回退成另一种命令，
   产生"看起来对、实际错"的结果——这类 bug 比直接报错更难发现。
4. HTML 批量插入后必须做**结构校验**（标签平衡 + 浏览器实测定位），
   不能只看"字符串替换成功"。
