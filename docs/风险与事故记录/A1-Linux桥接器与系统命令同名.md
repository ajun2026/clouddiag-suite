# A1 · Linux 桥接器与系统命令同名冲突

**类别**：部署 / 设计
**发现时间**：2026-09-20
**状态**：✅ 已修复（二进制改名为 `clouddiag-bridge`）

---

## 现象

客户在 Linux 机器上执行 `bridge` 命令，期望调用系统网络工具，
实际却启动了我们的诊断桥接器，并在终端里弹出房间码输入提示：

```
$ bridge link
云端AI远程运维助手 · 桥接器 v0.6.4
服务器: wss://<服务器地址>
房间码(8位，例如 ABC12345):
```

客户的操作被中断，且终端被占用，观感上像是「程序卡死」。

---

## 根因

**可执行文件命名与系统命令冲突。**

| 工具 | 典型路径 | 来源 |
|---|---|---|
| 系统网络工具 | `/usr/sbin/bridge` | `bridge-utils` 软件包 |
| 我们的桥接器 | `/usr/local/bin/bridge`、`/opt/.../bridge` | 本项目 |

Linux shell 按 `PATH` 顺序查找同名可执行文件。若我们的桥接器所在目录
优先于系统目录，则 `bridge` 会命中我们的程序。

叠加因素：桥接器**无参数运行时进入交互模式**（阻塞等待房间码输入），
因此在被误执行时会「卡住」终端，而不是立刻报错退出。

---

## 影响范围

- **平台**：仅 Linux（Windows 无同名系统命令）
- **对象**：需要使用系统网络工具（`bridge` / `brctl`）的客户机器
- **后果**：客户无法正常使用系统工具；误运行诊断程序产生困扰；影响产品观感
- **数据安全**：无影响（不涉及数据损坏或泄露）

---

## 处置过程

### 客户端临时处置

```bash
# 1) 退出卡住的提示（Ctrl+C），清理残留进程
sudo pkill -f "clouddiag" || true

# 2) 定位同名文件
sudo find / -name "bridge" -type f -not -path "/proc/*" -not -path "/sys/*" 2>/dev/null

# 3) 将我们的桥接器改名
sudo mv /opt/clouddiag/clouddiag-bridge /opt/clouddiag/clouddiag-bridge.bak  # 按实际路径调整

# 4) 安装系统网络工具
sudo apt update && sudo apt install -y bridge-utils

# 5) 验证
bridge link                        # 应为系统网络工具
clouddiag-bridge -h                # 应为诊断桥接器
```

### 项目侧根治

| 措施 | 说明 |
|---|---|
| **二进制改名** | `bridge` → `clouddiag-bridge`（Windows：`bridge.exe` → `clouddiag-bridge.exe`） |
| **交互模式改进** | 无参数运行不再阻塞：非交互环境（无 TTY）直接打印用法退出；有 TTY 也仅提示用法并退出，需显式 `-interactive` 才进入交互输入 |
| **安装路径规范化** | 安装脚本安装到独立目录，并在检测到系统已有同名命令时提示 |

---

## 预防措施

1. **发布命令行工具前，先检查目标平台是否已有同名系统命令**
   （`bridge` 在 Linux 属于常见系统命令）
2. **交互式程序要设计「非交互环境的兜底路径」**——不能无条件阻塞 stdin
3. **跨平台测试要覆盖真实客户环境**（含客户已有的业务工具）
