# C1 · 环境文件误提交公开仓库（凭据泄露）

**类别**：安全
**状态**：⚠️ 文件已移除，**凭据需轮换**

---

## 现象

发布流程中，本地 `.env` 文件被一并提交到**公开仓库**，其中包含真实凭据：

| 泄露内容 | 风险 |
|---|---|
| AI 网关 API Key | 他人可调用 AI，产生费用消耗 |
| 桥接器上传校验密钥 | 可伪造上传请求，污染分析数据 |
| 管理员账号密码 | 可登录管理后台（最高权限） |
| 内部服务地址 / 路径 | 暴露内部拓扑与目录结构 |

---

## 根因

1. **发布工具绕过了 `.gitignore`**
   项目 `.gitignore` 中**本就有** `.env` 规则，但发布脚本直接用文件系统遍历
   收集文件（而非通过 `git`），因此 `.gitignore` 完全未生效。

2. **发布前缺少敏感信息扫描**——未把"扫描密钥/IP/凭据"作为发布的强制前置步骤。

3. **排除清单靠人工维护**——新增敏感文件时容易遗漏。

---

## 影响

- 凭据在公开仓库中暴露（可被任何人、含自动化扫描工具获取）
- **删除文件不足以消除风险**——历史提交中仍可追溯
- 下载过该版本的其它环境同样持有这些凭据

---

## 处置过程

| 措施 | 说明 |
|---|---|
| 移除文件 | 从仓库中移除 `.env` |
| 补充忽略规则 | `.gitignore` 增加 `!.env.example`（允许模板入库，禁止真实配置） |
| 发布工具加固 | 排除清单中**硬编码拦截** `.env` / `.env.*` |
| 提供模板 | 新增 `.env.example`（占位符，不含真实值） |
| 全仓库扫描 | 扫描全部文本文件，确认无其它敏感残留 |

---

## 预防措施

1. **发布工具必须尊重 `.gitignore`**（优先用 `git` 命令发布，而非文件系统遍历）
2. **发布前强制敏感扫描**（key / token / 密码 / 内网 IP / 域名）
3. **默认拒绝**：排除规则采用硬编码拦截敏感文件名，而非依赖人工维护
4. **`.env` 永不入库**——部署时本地创建；仓库只提供 `.env.example`
