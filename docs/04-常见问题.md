# 常见问题（FAQ）

## 部署类

### Q1：登录后立刻掉线，一直跳回登录页

**原因**：HTTP 环境下 `COOKIE_SECURE` 仍为 `true`，浏览器拒收非 HTTPS 的 Cookie。

**解决**：`.env` 中改为 `COOKIE_SECURE=false`，重启服务。

```bash
sed -i 's/^COOKIE_SECURE=.*/COOKIE_SECURE=false/' clouddiag-server/.env
sudo systemctl restart clouddiag-server
```

---

### Q2：上传日志包报「服务器错误」或「日志目录不存在，请重新上传」

**原因**：缺解压工具（最常见是 `7z`；`.rar` 场景可能缺 `unrar`）。

**解决**：

```bash
sudo apt install -y p7zip-full lzop unrar    # 或 unrar-free
# 验证
which 7z unrar lzop
7z i | grep -i rar
```

详见[事故记录 A2](风险与事故记录/A2-依赖缺失导致功能异常.md)。

---

### Q3：AI 功能全部不可用，日志出现 `legal header value b'Bearer'`

**原因**：`.env` 未被加载（缺 `python-dotenv`）或 API Key 为空。

**解决**：

```bash
./venv/bin/pip install -r requirements.txt    # 确保 python-dotenv 已装
grep OPENAI_API_KEY clouddiag-server/.env     # 确认 key 有值
sudo systemctl restart clouddiag-server
```

---

### Q4：AI 分析提示「所有通道均失败: ... 空回复」

**原因**：AI 网关临时抖动/限流，或推理模型的正文内容为空。

**说明**：当前版本已内置 **3 次重试（递增间隔）+ 推理内容兜底**。
若持续出现，说明网关本身有问题，可：

```bash
# 直连网关验证
curl -s $DEEPSEEK_BASE_URL/chat/completions \
  -H "Authorization: Bearer $DEEPSEEK_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"'$DEEPSEEK_MODEL'","messages":[{"role":"user","content":"hi"}],"max_tokens":50}'
```

---

### Q5：桥接器连不上服务器

**排查顺序**：

1. **协议对不对**：HTTP 部署用 `ws://`，HTTPS 部署用 `wss://`
2. **端口通不通**：`curl http://<服务器IP>:<端口>/api/health`
3. **安全组**：云服务器控制台是否放行端口
4. **房间码/令牌**：是否过期（房间有有效期）
5. **地址**：`PUBLIC_URL` 配置是否与实际访问地址一致

---

### Q6：端口冲突 / 换端口

**解决**：改环境变量即可，无需改代码。

```ini
# clouddiag-server/.env
SERVER_PORT=8080

# log-analyzer/.env
PORT=8081

# 记得同步 clouddiag-server 里的：
LOG_ANALYZER_UPSTREAM=http://127.0.0.1:8081
```

---

### Q7：Linux 上敲 `bridge` 弹出了诊断程序

**原因**：历史版本桥接器命名为 `bridge`，与系统网络工具（`bridge-utils`）同名。

**解决**：升级到 v1.0.0+（已改名为 `clouddiag-bridge`）。临时处置见[事故记录 A1](风险与事故记录/A1-Linux桥接器与系统命令同名.md)。

## 使用类

### Q8：诊断台和对话页有什么区别？

| | 诊断台（/diag） | 对话页（/chat） |
|---|---|---|
| 交互 | 选择 30 个诊断项 | 自由提问 |
| 输出 | 五段式结构化报告 | 自由文本 |
| 适用 | 标准问题排查 | 复杂问题追问 |

创建房间时会让你选择进入哪个界面，两者数据互通。

---

### Q9：诊断报告里的「不适用」和「失败」有什么区别？

- **不适用**：客户机本来就没有这个硬件/功能（例如台式机无电池）——属正常
- **失败**：应该采到但没采到（例如该有的事件日志读取报错）——可能影响结论

这个区分是为了避免把「不存在」误判为「有问题」。

---

### Q10：AI 给的分析结论可信吗？

诊断报告的**【初步判读】**段落定位是**方向提示，不是结论**：

- 只提示「数据指向哪些方向」「优先关注什么」「下一步核验什么」
- 禁止武断表述（如「肯定是硬盘坏了」），不给更换硬件的建议
- 数据不足时会明确写「当前数据不足以判读方向」

**最终处置由工程师判断**——这是设计上的边界。

### Q13：内网部署（FRP 穿透）后桥接器连不上

**原因**：`PUBLIC_URL` 未改成穿透后的公网地址。

```bash
# 内网服务器上检查
grep PUBLIC_URL clouddiag-server/.env
# ❌ 错误：http://192.168.1.100:8000（内网地址，外部访问不到）
# ✅ 正确：http://公网IP:8000  或  https://域名
```

或对外协议与 `COOKIE_SECURE` 不匹配（HTTP 环境设了 `true` → 登录后掉线）。

完整排查见 [deploy/frp-internal/README.md](../deploy/frp-internal/README.md)。

### Q12：如何升级到新版本？

**务必先备份**，并按文件比对（避免旧文件覆盖现网修复）：

```bash
# 备份
TS=$(date +%Y%m%d-%H%M)
mkdir -p ~/backups/$TS
tar -czf ~/backups/$TS/clouddiag-suite.tar.gz -C /opt/clouddiag --exclude=venv .

# 升级
cd /opt/clouddiag
git fetch --tags
git diff <旧tag> <新tag> --stat    # 先看改动范围
git checkout <新tag>
sudo systemctl restart clouddiag-server clouddiag-loganalyzer clouddiag-logconsumer
```

详见[部署指南 · 升级与回退](01-部署指南.md#升级与回退)。
