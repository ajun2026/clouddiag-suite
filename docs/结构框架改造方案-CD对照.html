三句话结论
  1. 学的是三层骨架（作业对象 → 可执行对象 → 状态与留痕），不是界面；界面保持我们已有风格。
  2. 我们缺的是 「计划先行 / 状态门控 / 留痕汇聚」 三件结构性能力，底层能力一样不缺。
  3. 我们的真能力（真桥接器、真 AI 诊断、真日志分析、真权限）按 「插槽」 方式接入，不重写；5 步落地，只有 1 步碰后端。

一、三层骨架：他们怎么搭，我们差在哪

① 作业对象层
C/D：房间 / 工单 / SN / 客户常驻页头，每一步都知道在给谁干活
我们：数据早已存在（服务端房间表含 room_code / sn / engineer / status / diagnosis / last_seen），但页面几乎不展示（诊断台 0 处）。
结论：只补展示 面包屑 + 状态胶囊 + 终端三值，不动数据层。
② 可执行对象层
C/D：工具即对象 —— 分级（只读/写/刷写）+ 风险话术 + 预计时长 + 4 步计划；点开先看计划，确认后才执行
我们：零件都在（诊断项 40 条、工具 26 项已是 JSON 单一来源派生），但字段只有 key/icon/title/platform/group/prompt，没有 risk / dur / plan，计划先行 0 处。
结论：加字段 + 加一步确认 执行链路完全不动。
③ 状态与留痕层
C/D：状态机驱动界面（待触达 → 检测完成 → 已回写），AI 结论按状态回流；所有动作过同一个留痕出口
我们：有状态也有留痕，但都散着（服务端分级审批 106 处、快照回滚 22 处；页面留痕仅 1–2 处）。
结论：收口 状态胶囊 + 统一留痕面板（唯一需要新增后端出口的一步）。

改造后的结构

① 作业对象：房间 → SN / 机型 / 客户 / 工单 / 工程师 / 桥接器版本 → ② 可执行对象：诊断项 / 工具（+ risk / dur / plan） → ③ 状态与留痕：状态线 + 单一留痕出口 + AI 副驾两出口
查看计划→ 确认→ 桥接器真执行→ 步骤条 + 终端流→ 结论 / 报告→ 出报告 或 升级二线

六、风险与验收口径

  • 改动方式：全部加法式（新增 key / 新增函数），改前快照 + 一句话回退命令。
  • prompt 同步：任何 AI 口径调整必须同步三处消费路径（服务端三段 + JSON + 页面），改完用异语言样本验收字段数。
  • 验收方式：真机跑通「收集 → 诊断 → 工具执行 → 结论/报告」全链路；逐元素对比度复算；真浏览器主路径回归；旧结构无残留。
  • 不改变：内部功能、接口、既有操作习惯（第 2 步新增的确认弹窗为前插一步，不替换原有审批流）。
