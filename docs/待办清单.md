## T1 摘要

**问题**：服务端对 `role=field` 硬性禁止对话，而 `/field` 现场作业台的主要使用者就是上门工程师。
**结果**：53 个作业项里 14 项（有独立 HTTP 端点）可用，39 项走 AI 通道被拦，批量执行对 field 账号几乎不可用。
**要定的事**：白名单边界 / 权限模型 / 是否保留自然语言判读 / 审计方式。

## T3 摘要（2026-10-29 记录 · 后续再设计）

**现状**：登录页「忘记密码」= `alert('请联系管理员重置密码')`，没有任何自助能力；
真正的重置只有一条路——管理员登录后台 → 用户管理 → 重置密码 → 手工告知本人。
问题：管理员不在线就没人能改、员工不知道找谁、新密码还要在聊天里传。

**候选方案**

| 方案 | 做法 | 成本 | 依赖 |
|---|---|---|---|
| A 人工重置 | 维持现状，仅把文案写清「联系谁」 | 10 分钟 | 无 |
| **B 一次性重置码** | 管理员后台点「生成重置码」（6 位 / 20 分钟 / 一次性）→ 电话报给本人；登录页输入 工号 + 重置码 + 新密码自助改 | 半天 | 无（**建议先做这个**） |
| C 邮件自助重置 | 输入工号 → 发重置链接到邮箱（30 分钟一次性 token）→ 点链接设新密码 | 1.5 天 | **SMTP / 内部邮件中继（关键卡点，需 IT 提供）** |
| D 企业 SSO/LDAP | 用域账号登录，系统不存密码 | 3~5 天 | IT 配合 |

**C 方案技术要点（备查）**
- `users` 表当前**没有 email 字段**；但账号约定是「工号 = 邮箱前缀」，可用 `email = username@MAIL_DOMAIN`（`MAIL_DOMAIN` 走 .env）推导，存量账号零迁移；非企业邮箱账号才需单独存 email。
- 新增 `password_resets` 表：token 哈希 / 工号 / 到期 / 是否已用 / 请求 IP。
- 安全：token 只存哈希、一次性、30 分钟过期；页面不暴露账号是否存在；同工号 10 分钟最多 1 封、同 IP 每小时最多 5 次；请求与完成都写日志。
- 新增页面：登录页「忘记密码」弹窗 + `/reset?token=` 设置新密码页。

**待决策（下次讨论时先定这三条）**
1. 企业邮箱 SMTP / 内部中继能否申请到？（决定 C 能不能做）
2. 先做 B（不依赖 SMTP，当天可用）还是等 SMTP 直接做 C？
3. 账号表是否现在就加 `email` 字段（B 用不上，C 必须先有）。

## T4 摘要（2026-11-03 记录 · 主人决定后续再做）

**问题**：现在报告是「当场现算、看完就关」——`GET /api/room/report/{房间}?view=client|full` 每次用当时的事件流重新生成。
后患：① 事件超过保留期（默认 180 天）被清理后，报告再也生成不出来；② 结单归档后房间历史调不出原件；③ 结论算法以后一改，当年发给客户的那份就不是原件了。

**要做的事**：结单时把 `客户版 + 内部版` 两份 HTML 落到 `reports/`，文件名带版本号（`AP7RJNUF-v1-client.html` / `-v1-internal.html`），并在 `rooms.report_path / report_version` 记下版本与文件位置；报告页加「存档」按钮用于手动补存。
参考：结单 txt 报告的落盘逻辑已存在（`_room_close` + `REPORTS_DIR`），HTML 版沿用同一套即可。

**待拍板（下次开工前先定这三条）**
1. 存报告时机：结单自动存（建议）还是只在手动点「存档」时存？
2. 存几份：建议客户版 + 内部版各一份。
3. 谁能看：建议现场处理人/二线看自己房间、管理员看全部；**不建议**给免登录只读链接（拿到链接即可看客户数据）。

## T5 摘要（2026-11-03 记录 · 观察期至 2026-11-10）

**现状**：现场台 / 二线台的「调用记录」与「原始日志」两张区块**只是界面隐藏**，代码一行没删。
隐藏方式：`field-console.html` / `expert-console.html` 里一行 CSS

```css
/* 2026-11-03：调用记录与原始日志已由「轨迹」取代（信息全部进事件流），界面隐藏、DOM 保留便于恢复 */
#resPreview,#termCard,#resultCard>.card-head{display:none!important}
```

删掉这一行即恢复显示，不需要动备份。

**为什么敢隐藏**：两区块的 16 类信息已全部埋进 `events`（`POST /api/room/event` 上报）：
审批请求/批准/拒绝 · 升级二线 · 工号确认/门禁拦截 · 批量执行开始/结束 · 日志采集开始/完成/失败 · 上传/删除附件 · 查看/定稿报告 · 执行失败原因；命令原文与输出由 `op.call` / `op.result` 覆盖。
「执行通道等待条」已从原始日志里移出，挂在作业项卡片顶部（始终保持可见）。

**彻底删的时候要动的位置（勘察结果，届时照着删）**
1. HTML：`#resultCard` 整块（含 `#resPreview`、`#termCard`、`#term` 容器）——两台各一处
2. HTML：`#resExpand` / 执行结果模态 `#resMask`（若确认不再需要全文弹窗）
3. JS：`term()` 函数与 `NP.term` 引用（共 24 处调用点，可改为只写 `NP.ev`）
4. JS：`paintAudit()` / `NP.audit()`（26 处调用点，可改为空实现或并入 `NP.ev`）
5. CSS：`#termCard.term-fold` / `.term-sum` / `.term` 相关规则
6. 删完回归：四张卡跑一遍 + 结单 + 报告 + 轨迹，确认无 `undefined` / 空白区

**观察期要确认的问题（如有任一条成立就不能删）**
