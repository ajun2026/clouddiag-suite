# 英文版 Windows 客户机 · 自测清单

> 背景：解析层如果只认中文标签（例如「停止错误」「非正常关机」），英文系统上的采集会**静默返回空结果**——不报错，但结论会误报「未检出」。这是最容易在客户现场翻车的一类问题，必须用英文系统实测。
>
> 适用版本：服务端 ≥ 1.4.6，桥接器 ≥ 1.4.2

---

## 0. 准备

| 项 | 要求 |
|---|---|
| 客户机 | 英文版 Windows 10/11（`en-US`，语言包为纯英文，不要装中文语言包） |
| 桥接器 | 现场台「连接客户机」→ **下载 .bat（exe 版）**，双击运行，窗口显示 `ver=1.4.2` 或更高 |
| 网络 | 能访问 `https://agent.l2aihub.com` |
| 记录 | 每步结果截图或文字记录，失败项附「原始输出」 |

---

## 1. 逐项操作与预期

| # | 操作 | 预期结果 | 失败判定 |
|---|---|---|---|
| 1 | 新建房间，SN 填任意值 | 房间创建成功，房间名形如 `<单位>-<机型>-<SN>-<MMDD>` | 建房失败 / 名称乱码 |
| 2 | 点「死机、蓝屏」→ 运行 | 6 步全部「已调查」；有蓝屏记录时结论里出现**停止码**（如 `0x0000007a`） | 结论写「未检出」但客户说有蓝屏 → 疑似解析失配 |
| 3 | 点「自动重启」→ 运行 | 41 / 6008 / 1074 三个数字分别显示；人为重启多时结论为「未发现异常」 | 三项全是 0 但客户说经常自己重启 |
| 4 | 点「卡顿」→ 运行 | 结论含 CPU 占用前三、系统盘可用空间 | 进程/磁盘为「未检出」 |
| 5 | 点「花屏、闪屏」→ 运行 | 结论含**分辨率 × 刷新率**、显卡清单 | 显示「× @ Hz」（空值） |
| 6 | 自由模式问一句「本机最近有什么异常」 | AI 正常回答，且引用了真实数值（不只泛泛而谈） | 报错 / 回答与采集数据无关 |
| 7 | 升级收集 → 日志采集 | `TSLOG_DONE … .7z` 或 `.zip`，大小几十 MB | `TSLOG_NO_PACKAGE` |
| 8 | 远程桌面观察 | 画面为 **16:9 主屏**，点画面能放大 | 超宽条 / 黑屏 / 报错 |
| 9 | 顶栏「轨迹」 | 时间轴按顺序列出：登录 → 开始检查 → 执行命令 → 检查完成 | 空白 / 报错 |

---

## 2. 专项：字段级核对（关键）

在「死机、蓝屏」跑完后，点开「蓝屏记录（事件 1001）」那一步，**逐字核对**：

- [ ] 表头显示 `时间 / 事件ID / 来源 / 内容`（不是 `time / id / src / msg`，也不是空白）
- [ ] 内容列是**英文**的 BugCheck 描述，仍能从中看到 `0x` 开头的停止码
- [ ] 若 0 条：页面显示灰色「0 条记录（本次查询无匹配事件）」，而不是空白

> 这一项失败通常意味着：服务端从事件消息里抽停止码的正则只匹配了中文（如「检测错误」），需要补英文（`The computer has rebooted from a bugcheck`）。

---

## 3. 失败时怎么取证（交给旺财）

1. 该步骤下方表格的截图（或「0 条记录」提示）
2. 点「轨迹」→ 找到对应的「执行命令 / 命令输出」两行 → 点「查看完整输出」→ 复制全文
3. 服务端核对命令：把上面的全文发回，即可判定是「命令没查到」还是「查到了但解析失配」

---

## 4. 通过标准

- 第 1–9 项全部符合预期
- 「专项」三条全部勾选
- 轨迹页能完整复现本次操作（登录 → 4 张卡 → 采集 → 观察）

全部通过后，可在 `docs/待办清单.md` 中关闭「英文系统解析」这一项。
