## 二、这一版的核心：操作轨迹（Trajectory）

### 2.1 设计原则（一句话）

**事件日志是唯一真相，轨迹只是它的只读投影。** 不为"展示"单独建数据，展示层从事件流纯函数推导——所以视图可以随时增删、永不与事实打架。

### 2.2 数据层：`events` 表

`logs/chat.db` 中的 append-only 表（只追加，永不 UPDATE/DELETE；修正靠追加 correction 事件）：

| 字段 | 含义 |
|---|---|
| `id` | 事件唯一 ID |
| `stream` / `seq` | 流名（`room:房间号`）+ 流内严格单调序号，`UNIQUE(stream, seq)`，是分页/补页的唯一游标 |
| `room_code` | 房间号（跨房间查询用） |
| `ts_srv` / `ts_src` | 服务端收到时刻 / 源头时刻 |
| `kind` | 事件类型（见下表） |
| `actor` / `actor_role` | 谁做的（账号 + 角色） |
| `turn` / `step` / `parent` | 层级关系放在信封上，不塞进 data |
| `data` | JSON 业务字段 |

### 2.3 事件类型（共 25 种）

| 组 | 事件 | 记录时机 |
|---|---|---|
| 房间 | `room.created` | 建房时（时间轴起点） |
| 登录 | `auth.login` | 登录成功 |
| 桥接器 | `bridge.connect` / `bridge.disconnect` | 客户机接入 / 断开（含原因与累计次数，10 秒内重复 identify 去重） |
| 诊断 | `diag.step.start` / `diag.step.end` | 每步开跑 / 完成（`data_rows` 结构化结果一并入库） |
| 命令 | `op.call` / `op.result` / `op.error` | 命令原文（**下发前**先记，checkpoint 纪律）/ 输出摘要 + 全文引用 / 失败原因 |
| 结论 | `diag.conclude` | 初步结论（等级 + 结论句 + 事实明细） |
| 批量 | `diag.batch.start` / `diag.batch.end` | 批量执行开始 / 完成（成功数、失败明细） |
| 审批 | `approval.request` / `approval.approve` / `approval.deny` | 服务端请求审批 / 现场批准 / 拒绝 |
| 门禁 | `gate.confirm` / `gate.blocked` | 工号确认通过 / 门禁拦截（原因） |
| 升级 | `room.escalate` | 升级给二线（升给谁） |
| 采集 | `artifact.collect.start` / `artifact.collect.end` / `artifact.uploaded` | IDG 日志采集开始 / 完成（文件名/大小/耗时）或失败 / 上传成功 |
| 文件 | `file.uploaded` / `file.deleted` | 房间附件上传 / 删除 |
| 报告 | `report.viewed` / `report.archived` | 查看报告（存档版或实时）/ 报告定稿 |
| 工具 | `tool.result` | 整包类工具（驱动/SMART/BIOS/能源/OA3）执行结果 |
| 协作 | `im.message` | 协作消息 |
| AI | `ai.turn` / `ai.answer` | 提问 / 回答（现场台走 `/api/ai_qa`，不是 WS chat） |

### 2.4 写入通道（两条）

| 通道 | 用途 | 位置 |
|---|---|---|
| 服务端内部 `record_event()` | 登录、房间、桥接器、步骤、命令、结论、上传 | `server.py` |
| 前端上报 `POST /api/room/event` | 审批、门禁、批量、采集、文件、报告、工具结果 | 现场台/二线台 `NP.ev()` |

**安全约束**：上报接口带登录校验 + 房间权限校验 + **26 种 kind 白名单**（非法 kind → 400）+ 字段长度限制（单字段 300 字、数组最多 10 项）+ **`actor` 一律取登录会话**（前端传什么用户名都不认）。

### 2.5 读取层（两个接口）

| 接口 | 作用 |
|---|---|
| `GET /api/room/events?room_code=&limit=&before_seq=&view=full\|client` | 轨迹投影，需登录 + 房间权限 |
| `GET /api/room/event/{id}/blob` | 取某条 `op.result` 的完整命令输出（鉴权 + 路径防穿越） |

**大输出处理**：命令输出超过 400 字时，全文落盘 `room_event_blobs/<房间>/<随机id>.txt`，事件里只存摘要 + 引用路径 + SHA256 前 16 位。实测 1684 字输出 → blob → 鉴权读取 200，未登录 401。

### 2.6 客户版投影（Surface 简化版）

**关键决策：脱敏在服务端做，不是前端藏。** 前端藏的内容仍能在网络响应里看到，等于没藏。

`view=client` 时服务端返回另一套投影：

| 隐藏 | 保留 |
|---|---|
| 命令原文（改「命令内容已隐藏」） | 时间、角色 |
| 输出预览（改「N 字符（内容已隐藏）」） | 动作名（下发检查命令 / 检查完成 / 给出结论…） |
| 附件下载链接 | 结果规模（采集 N 条数据） |
| 账号名（只留角色：现场/二线/系统） | 结论等级与结论句 |
| 主机名（改「客户机已连入」） | 机器身份（SN/机型/客户单位） |
| 执行毫秒（易被误读成"卡顿时长"） | 桥接器版本 |
| 文件路径、IP（替换 `[已隐藏路径]` / `[已隐藏]`） | |

实测（抓原始 JSON 扫）：`"command"` / `"preview"` / `"blob"` / `data_rows` / `C:\` 路径 / IP / 账号 全部为 **False**。

### 2.7 保留期与清理

- 默认 **180 天**，`.env` 可用 `EVENTS_RETENTION_DAYS` 调整
- 每 6 小时跑一次清理：删过期事件 + 删 7 天未动的 blob 文件

### 2.8 轨迹页（`/trajectory?room=`）

时间轴正序（从上到下 = 现场发生顺序）、角色徽章、点击展开原文、按角色筛选、15 秒自动刷新、「加载更早」分页、客户版开关、`op.result` 显示「查看完整输出」链接。

**入口**：现场台与二线台作业区右上角「轨迹」按钮。

**鉴权**：`/trajectory` 与 `/static/console/*.html` 未登录一律 303 跳登录（此前匿名可打开空壳页，属漏洞）。

### 2.9 踩过的坑（留档）

| 问题 | 真因 | 修法 |
|---|---|---|
| 轨迹里全是历史登录 | 按房间参与者合并**全部**登录事件 | 只在房间生命周期内（建房起）+ 同一人 30 分钟内只留一条 + 最多 8 条 |
| AI 事件缺失 | 埋点挂在 WS `chat`，现场台实际走 `/api/ai_qa` | 在 `ai_qa` 内补 `ai.turn` / `ai.answer` |
| 步骤命令没记录 | `_skip_ev` 把 `step_` 前缀也跳了 | 只跳 `shot/nshot/probe` |
| 顺序颠倒 | `ORDER BY ts_srv DESC` | 改 `ASC, rowid ASC` |

## 三、诊断报告（P1）

### 3.1 接口

`GET /api/room/report/{房间号}?view=client|full&download=1` → 独立 HTML（内联 CSS，可离线、可打印）

### 3.2 报告结构（五段）

作业信息（客户单位/机型/SN/工单/房间/处理人/作业时段+总时长）→ 诊断概览（每张卡：步数、数据行、耗时、失败步、结论）→ 关键数据（结论事实明细）→ 操作记录（客户版已脱敏）→ 附件清单（文件名/大小/时间，不含路径）

### 3.3 客户版 vs 内部版

| 项 | 客户版 | 内部版 |
|---|---|---|
| 命令原文 | 不出现 | 完整 PowerShell |
| 输出 | 「采集 N 条数据」 | 字符数 + 可查全文 |
| 处理人 | 姓名（如 张三） | 登录账号 |
| 主机名 / IP / 执行毫秒 | 隐藏 | 保留 |
| 结果回传与断开噪声 | 过滤 | 全保留 |

### 3.4 入口

现场台/二线台作业区右上角「报告」按钮 → 新窗口打开客户版；报告页顶部可切「客户版 / 内部版 / 下载 HTML / 打印存 PDF」。下载走 fetch+Blob，**页面不跳转**。

### 3.5 这一版修掉的 4 个毛病

1. 操作记录里步骤行整段丢失（卡片统计分支把步骤吞了）→ 修
2. 「客户机接入」重复两行（桥接器 10 秒内重复 identify）→ 写入去重 + 读取去重
3. 毫秒耗时被客户误读成"卡顿时长"→ 客户版改说「采集 N 条数据」
4. 角色显示英文 `system` → 补中文映射

## 五、实用工具修复（本轮重点）

### 5.1 问题

除「开机自启动」外，实用工具里其余工具**数据取回来了但界面看不到**：因为它们的执行结果只写进「调用记录 / 执行结果」，而那块已被隐藏。等于点了运行白跑。

### 5.2 三处改动

| 改动 | 说明 |
|---|---|
| **结果就地渲染** | 新增 `renderPack()`：整包类工具的真实返回直接显示在计划面板下方（首 18 行 + 「展开全部 N 行」按钮 + 行数），失败直接显示原因。样式 `.ipl-pack` |
| **OA3 端点修正** | 卡片 key 是 `oa3_activate`，端点表里写的是 `activation` → 一直没发真请求；补映射后实测 `/api/tools/oa3/read` 200 |
| **删除「接收文件到客户机」** | 现场台+二线台各删一份（NP_DATA 52 → 51），实用工具 10 项 → 9 项 |

### 5.3 结果同时进轨迹

每个整包工具执行后前端上报 `tool.result`（tool/key/chars/rows/ms），实测落库。

### 5.4 未接的两个写操作（待议）

| 工具 | 现状 |
