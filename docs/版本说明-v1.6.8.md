# 版本说明 · v1.6.8

> 发布日期：2026-11-05｜服务端 1.6.8 ｜二线台 v0.17.0
> 主题：**创建房间只填 SN**，SN 有效性以联想官网为准；二线台「整机档案」接真实数据源

## 一、创建房间：只要「客户单位 + SN」

| 变更 | 说明 |
|---|---|
| 删除「工单号」「机器型号」两栏 | 现场端 `/field` 与二线端 `/expert` 同步删除（含演示用的「自动识别」按钮，原先是按 SN 哈希伪造的假数据） |
| 保留「客户单位」（必填）+「SN」+「客户机系统」 | 客户机系统仅决定下载哪种连接文件，桥接器上线后仍会自动纠正 |
| 机型 / MTM 自动带回 | 由联想官网接口按 SN 取回，直接写入房间并生成房间名 `客户单位-机型-SN-日期` |

## 二、SN 有效性校验（联想官网 ASP）

接口：`/api/sn_check?sn=` → 旁挂 `/asp_warranty` → 联想官网 `getDeviceInfo`（无需登录、无验证码）。

| 状态 | 判定 | 创建按钮 |
|---|---|---|
| 🟢 绿 | SN 有效且在保 | 可创建 |
| 🟡 黄 | SN 有效但已过保 | 可创建（过保仍允许，后续再议拦截） |
| 🔴 红 | 格式非法 / 官网查不到 | **禁止创建** |
| ⚪ 灰 | 官网不可用（超时/5xx） | **禁止创建**（待优化 T8，见 `docs/待办清单.md`） |

- 弹窗内联显示：`SN 有效 · 在保 · 保修至 2029-01-03` + `机型 · MTM · 生产日期` + `出厂配置：i9-12900K 32G x2`
- 服务端在 `/api/rooms` 内部**复校验一次**，绕过前端直接 POST 同样拦得住
- 校验结果写入操作轨迹 `sn.check`，描述含「是否有效 / 保修情况 / 机型 / MTM / 生产日期」

## 三、二线台「整机档案」接真实数据

新增旁挂服务 `mofang-profile/`（FastAPI，仅监听 `127.0.0.1:8081`，Bearer 鉴权）：

| 数据 | 来源 | 说明 |
|---|---|---|
| 保修 / 历史维修记录 / 出厂配置（BOM） | 魔方服务（IPS/SF） | 服务账号登录 + 会话保活；按 SN 缓存 |
| 官网档案（机型/MTM/生产日期/保修起止/出厂配置简称） | 联想官网 ASP | 轻量补充源，5 秒超时，失败静默降级 |

- 左栏三项「保修 / 出厂配置 / 历史维修记录」可点击，弹窗显示明细（装箱单 100+ 行走可滚动表格）
- 界面新增 **MTM** 一栏；机型附近展示 MTM
- 「工单」栏语义修正为**进行中工单**：历史维修单号绝不回填；有在修工单但拿不到单号时显示「N 个进行中（单号待查）」
- 权限：整机档案仅 `expert` / `admin` 可见，现场端显示「仅二线账号可查」

## 四、升级要点

1. 新增环境变量（主服务 `.env`）：
   ```
   PROFILE_WARRANTY_URL / PROFILE_CONFIG_URL / PROFILE_REPAIR_URL / PROFILE_ASP_URL
   PROFILE_*_TOKEN / PROFILE_TIMEOUT=180
   SN_CHECK_URL / SN_CHECK_TIMEOUT=15
   ```
2. 旁挂服务需单独部署：`mofang-profile/`（依赖 `cairosvg`、`ddddocr`），可用 systemd 托管
3. 数据库自动加列：`rooms.mtm`（启动时 `_ensure_column`，老库无需手工迁移）
